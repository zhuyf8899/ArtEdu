## 具体原因

1. 输出预算与网页写入策略不匹配：要求一次写齐完整页面，但复杂代码集中在工具参数内，2400 输出 token 下被截断。候选拦截避免了坏文件，却没有拆分写入或恢复执行，任务仍失败。
2. 多产物编排缺少稳定的分项推进：文档结构约束不充分，重复生成文档消耗调用；转向网页又截断。缺项能被识别，但缺项的补齐策略仍不足。
3. 中文确认识别有确定性缺陷：`apps/api/src/modules/agent/agent-tools.ts:89` 的正则要求“确认”后出现空白或标点，无法接受“确认启动……”这种常用表达。需要动作与目标绑定的授权状态，不能只扩充几个关键词。
4. 图片验收只检查文件存在和 MIME，未验证画面。模型依据请求描述复述“无文字”，与实际水印不符。供应商水印行为需另查，不能默认可以移除。
5. 展示层能反映 failed、partial、paused、needs_confirmation，并保留实际 Word/图片入口；但“已完成”的判据仍只覆盖工具和文件，不能自动代表视觉要求达标。
