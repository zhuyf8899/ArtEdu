# 工作流节点库扩充（2026-10-18，第二轮）

第一轮的交互与执行修复见 [workflow-repair-20261018.md](workflow-repair-20261018.md)。本轮在**不改变平台执行引擎定位**（线性 DAG + 数据依赖）的前提下，把画布里只能"摆着看"的空白补成了真正能跑的节点，并加入两个可直接插入的示例链路。

## 新增的 9 种平台节点

| 类型 | 名称 | 输入端口 | 输出 | 语义 |
| --- | --- | --- | --- | --- |
| `text_constant` | 文本常量 | 无 | 文字 | 保存一段可复用文字，作为链路起点的数据源 |
| `text_join` | 文本拼接 | `a`、`b` | 拼接后的文字 | 严格按 A、B 端口顺序拼接，保留重复文字，分隔符可留空 |
| `text_replace` | 查找替换 | `input` | 替换后的文字 | 普通文字精确匹配（不是正则），替换内容可留空 |
| `text_template` | 提示词模板 | `input` | 模板文字 | 仅支持 `{text}`、`{prompt}`、`{negative}` 占位符，未知占位符报错 |
| `text_to_prompt` | 文字转正向 | `input` | 正向提示词 | 把上游文字设为新的正向提示词，并清掉冲突的负向/原始文字载荷 |
| `text_to_negative` | 文字转负向 | `input` | 负向提示词 | 转为负向条件；超过 1500 字拒绝执行 |
| `text_preview` | 文字预览 | `input` | 文字 | 展示中间或最终文字，可作为流程终点，也可继续接下游 |
| `reroute` | 数据转接 | `input` | 原样数据 | 原样透传一路数据，只允许且必须连接一路输入 |
| `result_select` | 结果选择 | `a`、`b` | 选定的一路结果 | 选用 A 或 B 的完整结果；**两路上游都会执行**，不节省模型调用 |

## 端到端落地位置

- 前端节点元数据、端口与模板：`admin-console/src/platformNodeCatalog.js`
  - 节点按分组进入节点库（文字处理 / 提示与教学 / 输出与说明 / 流程控制），支持搜索与拖拽。
  - 两个示例链路："提示词整理模板"（常量 → 替换 → 模板 → 转正向 → 预览）、"文字拼接模板"（两路常量 → 拼接 → 预览）。
- 前端发布预检与"下游是否自带提示词"判定：`admin-console/src/workflowExecution.js`
  - 替换/模板的必填内容、A/B 端口完整性、模板占位符是否有上游数据，均在保存前拦下。
  - 只有当前输入的下游确实带着提示词，才允许把「创作需求」当可选；另一条分支的提示词不会误让输入变可选。
- 后端类型清单与参数校验：`apps/api/src/modules/studio/workflow-text-nodes.ts`
- 后端契约：`studio.contracts.ts`
  - 节点类型枚举纳入 9 种新类型；输入端口必须存在且不可重复连接；输出端口只允许 `output`。
  - `data` 允许 `separator`、`find`、`replacement`、`selection` 随版本保存。
- 后端执行与合并：`studio.service.ts`
  - `text_join` / `result_select` 按端口取上游，不依赖连线数组顺序。
  - 执行后文字上限 10000 字，超限报错而不是把无限增长的数据传给模型。
  - 预检区分"草稿可缺输入"与"发布必须可执行"：无图片来源的保存节点、合并节点缺上游、模板占位符缺数据都会拒绝发布。

## 仍不支持的（明确边界）

- 一般条件分支、循环、失败分支、节点级重跑：当前不是通用工作流引擎，画布是线性 DAG，这些属于功能需求而非缺陷修复。
- 未接入真实执行服务的 GPU 节点（`lora`、`controlnet`、`upscale`、`text_encode`、`load_checkpoint`、`vae_decode`）仍拒绝发布。
- 目录分页（超过 20 个工作流后的浏览入口）未在本轮处理。
