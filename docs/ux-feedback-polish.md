# 体验反馈完善说明

本轮按“先完善体验闭环”的顺序，为门户与管理后台统一了操作反馈、确认和恢复机制。

## 统一反馈入口

- `FeedbackProvider` 在应用根节点维护消息队列和确认对话框。
- 页面使用 `notify(message, tone)` 展示成功、错误或信息提示，不再各自维护计时器。
- 停用用户、发布/驳回作品、撤销 Bridge、删除任务和笔记必须先通过 `confirmAction`。
- 错误提示保留更长时间，并允许用户主动关闭。

## 可恢复页面状态

- 首页、教学资源、案例社区、我的学习和管理台均区分加载、失败与空数据状态。
- 失败状态提供“重新加载/重新连接”，避免 API 短暂不可用后只能刷新整页。
- 搜索 API 不可用时继续展示本地聚合结果，并明确标注降级状态。

## AI 创作输入

- `/api/portal/home` 新增 `creation` 快照，展示模型服务状态、可用模型数量以及当前用户的日/月/并发额度。
- 该快照只用于前端提示；任务创建仍由服务端在事务内重新校验额度。
- 未提交的创作输入按账号保存到浏览器 `artedu.ai-draft.<userId>`，任务创建成功或用户主动清空时删除。
- 模型执行未启用、额度不足和附件功能尚未开放时均给出明确说明，不生成虚假的成功结果。

## 验证

提交前执行根目录 `npm run check`，覆盖 API TypeScript 检查、18 项安全/契约测试、前端生产构建和 4 项 Sites Worker 测试。
