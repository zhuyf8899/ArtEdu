## 当前确认的缺口

### D01 · P1：九个结构化试学原子及连接课程未迁移

本地 24 项修复验收曾发布色彩、字体、网格三门试学课拆出的九个教学原子，以及“设计表达入门 · 原子学习路线”。线上 `atomic_starter_sources` 为 0，完整课程列表只有交接《信息图表设计》，没有该试学路线。

现有三门旧试学课仍各有三个公开课时，并没有全部删除；它们在“课程库”。新原子库中的同名条目属于另一批交接大纲，不能代替原来含教学目标、练习、图例及评价流程的九个试学原子。

建议：保留 30 个交接原子，同时从已核对的九个试学课时恢复原子版本、知识绑定、课程引用和来源；由真实教师及另一审核人员按原流程确认。不复制示例进度，不把旧课程完成点击转成能力认证。

### D02 · P1：导入原子没有负责教师，普通教师审核链路未完成

线上 30 个教学原子归属禁用的资料库记录，教师拥有的公开教学原子数为 0。当前权限只允许原原子的负责教师审核关联心得，管理员/运营可审核全部符合范围的内容。因此学生向交接原子提交心得后，普通教师无法依现有归属规则在自己的审核队列接到它；管理员/运营审核能力仍存在。

建议：为导入原子或课程设置真实的负责教师/审核分配，保留原稿作者署名和资料来源。不要创建冒名教授账号，也不要简单放开所有教师编辑/审核全部内容的权限。

### D03 · P1：工作流版本数据落后于本地验收状态

当前三条工作流均仅有 V1：“案例分析工作流”“图片生成工作流”“正负提示词图像生成”。本地旧实测报告明确记录“正负提示词图像生成”后台已发布 V4。

工作流公开版/私人草稿状态的修复代码已上线，但高版本节点定义和发布记录是数据库内容，不会随 Git 更新自动出现。本轮没有把 V1/V4 的全部节点和模型参数逐项重放，所以不能据此断言 V4 的每一个节点均缺失或 V1 无法生图。

建议：单独核对并迁移目标工作流的版本定义、节点关联及附件引用，保留原版本和真实引用，不直接把 V1 的版本号改成 V4；云端模型密钥及既有图生图适配不由本地配置覆盖。

### D04 · P2：学习计划只加载前 24 个原子

`LearningManagers.jsx` 的计划关联选择仅调用 `/catalog?view=atoms&page=1`，没有继续分页或服务端搜索。线上实际返回总计 30 个原子，第一页 24 个、第二页 6 个。因此“动捕实验室”“小组讨论、初步方案设计与研讨”“小组初步方案陈述与优化设计”“小组方案制作与辅导”“参观展览”“最终作业陈述”不会出现在这个选择框中。

这是最新代码也仍存在的联通问题，不是服务器漏部署某个修复提交。学生心得的关联原子选择器另有搜索和分页，不能把这个缺口误报成心得选择也只能看到 24 个。

建议：学习计划复用可搜索、可分页且保留版本的资源选择器，并包括完整课程；不要无限扩大一次加载上限掩盖问题。

### D05 · P2：课程路径建议仍只使用旧目录

当前建议模型按 COL-01、TYP-02、GRD-03 等旧课程 code 取内容，保存链接也固定为 `?course=`，没有把 30 个新原子和新发布的完整课程作为推荐对象。旧目录的“信息图表设计”仍是筹备课程，而新完整课程已经发布，用户在不同入口会看到不同的可学状态。

建议：统一旧课程、学习原子、完整课程的资源身份、开放状态及深链接；建议说明明确区分“交接大纲阅读”和“可练习课程”。当前确实是目录规则，不应改回声称已接入个性化 AI。

### D06 · P2：仍有无素材的公开示例案例

“云格新序：传统纹样的当代表达”仍为 approved，素材数量为 0，结构化来源信息为空。这不是刚恢复的九个 CVPR 精选作品之一，也不是本轮恢复时丢失的图片。

建议：从正式展示中隐藏或明确标为演示内容；真实课程和社区内容不受影响。需按内容管理流程处理，不直接删除用户记录。

### D07 · 发布管理：旧目录与未提交增量带来再次回退风险

原目录 `4de3081` 和新发布源 `f3c66d3` 并存。当前容器确实使用新发布源；若后续只在旧目录按默认构建命令重新部署，会重新构建旧代码。此外，交接课程详情和内容同步新增文件尚未全部进入 Git，直接拉取 main 也不足以复现当前云端增量。

建议：将当前已验证增量单独提交合并，使用唯一发布入口；每次部署同时验收代码版本、迁移、内容安装批次及上传卷。保持九个 CVPR 案例的独立发布包和当前数据库/媒体备份。

## 建议处理顺序

1. 先补 D01、D02、D03 的内容与负责关系：九个试学原子/路线、高版本工作流、真实教师分派；保持交接大纲和既有学习数据。
2. 再修 D04、D05：统一可分页资源选择与跨学习体系的课程路径建议；不需要重做全部 24 项修复。
3. 处理 D06 演示内容，并完成 D07 的独立提交、唯一部署入口及版本/数据验收。
4. 在隔离测试环境补学生上传心得 → 负责教师/管理员审核 → 分支可见 → 练习评价 → 画像证据，以及计划/笔记编辑的完整多角色回归。生产检查不通过创建假完成记录来验收。

## 本轮验证边界

- 已核对 GitHub 当前版本、公网入口、容器镜像来源、源码/编译文件、迁移和实际业务数据。
- 只读验证原子分页、完整课程目录、画像、学习面板、全站原子搜索、工具投稿列表和学生管理权限拒绝。
- 没有执行真实投稿、审核、进度写入、模型生成、工作流版本恢复或 UI 再次部署。没有新建登录会话或提取浏览器凭据。
- 本机数据库服务未启动，本地业务数据的比较依据是原修复验收文档、发布回执和已存的检查记录；不把旧文档中的数量当作当前本机实时状态。
- 线上页面的视觉效果、键盘交互及付费模型全链路不因“产物里存在代码”而自动视为通过。
