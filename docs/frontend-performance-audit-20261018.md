# 前端性能代码审查（2026-10-18）

范围：当前 React 门户、MORPH 动画、聊天和节点画布，以及本地生产构建产物。此次为代码与产物审查，没有在目标低配电脑采集浏览器 Performance Trace；不能据此宣称具体 CPU 占用、FPS 或最低硬件规格。没有修改运行代码或重新部署。

结论：浏览器端存在可避免的持续负担，首页星云最突出。服务端模型生成与用户电脑上的动画、布局、图片解码是不同负载，升级服务器不会解决浏览器主线程和绘制瓶颈。

| 优先级 | 页面/原因 | 代码证据 | 影响与建议 |

| 高 | 首页持续进行大量 Canvas 2D 运算 | `src/morph/cosmosEffect.js`：桌面 8,500 粒子 + 850 星点；移动端 3,600 + 300；`tick` 无帧率限制 | 桌面 60fps 约每秒 51 万次粒子更新，120fps 约 102 万次，另有绘制和星点更新。建议默认 30fps、按帧耗时调整粒子数并提供静态档。上述是循环次数推算，不是浏览器实测。 |
| 高 | 首页第二张全尺寸 Canvas 无实际绘制 | 同文件 `dust/dc`：初始化尺寸和变换，`drawWords` 每帧 `clearRect`，文字实际为 DOM | 可移除冗余画布；1920×1102、DPR 上限 1.65 时两张画布基础 RGBA 像素存储约 44MiB，不包括浏览器和 GPU 的额外缓冲。 |
| 中高 | 首页每帧修改 DOM 与模糊效果 | 同文件 `drawWords`：9 个文字元素每帧设置 opacity/filter/transform，标题每帧赋值 textContent | 文字内容仅变化时赋值，模糊固定分档或禁用，DOM 更新降低频率；实际重排和合成成本需浏览器录制确认。 |

已有的保护措施：

- 动画会在标签页隐藏、主体离开视口时停止，组件卸载也会清理；支持系统的 prefers-reduced-motion。
- 首页 DPR 已限制为 1.65；其他背景一般限制为 2；星云光点使用预渲染精灵避免逐粒子 blur。
- 大页面使用 lazy/Suspense；课程、案例封面使用图片懒加载。
- 聊天增量按动画帧合并，消息组件使用 memo，长对话有压缩和本地容量控制。

建议实施顺序：

1. 首页动画限 30fps，删除空画布，减少每帧 DOM 写入，加入可持久化的静态/流畅/完整效果设置。
2. 用实际帧耗时自动调节粒子和 DPR，避免仅凭屏幕宽度判断机器性能；减少动态效果偏好始终优先。
3. 对其他背景应用同一套动画预算，减少动态背景上的大面积 backdrop-filter。
4. 再处理字体/CSS首屏、IndexedDB 查询及节点草稿保存。

验收建议：同一浏览器、同一台电脑对比原版与优化版；分别测试首页静置、输入、滚动、切换页面、长聊天流式输出和节点拖动；覆盖 60/120Hz 与低性能设备。记录帧耗时分位数、长任务、输入延迟、JS/页面内存、CPU 和实际网络传输；另比较静态模式，并确认离开视口后动画停止。CPU 降速模拟可作为补充，不能替代真实低配机。

在实测之前，不给出“必须独显”或具体内存最低要求。按功能性质，普通学习、聊天和目录浏览应以常见集显电脑为优化目标；大规模节点图和大图预览的要求需单独测试。
