# 工作流交互与执行修复（2026-10-18）

本轮按“拖动 → 草稿保存和试运行 → 数据关系 → 相关异常场景”的顺序修复。节点种类没有批量扩充，只新增了完成正负提示词分支所需的 `prompt_merge`。

## 用户可见变化

- 节点的标题、说明、空白、参数标签和图片区域均可按住拖动。输入框保留文字编辑，端口保留连线操作；一次拖动仍可撤销。
- 首次保存草稿和已有草稿试运行均绑定明确版本 ID。保存失败不创建运行，保留画布，可重试；保存成功不再重新打开画布，也不会因目录刷新失败而把成功保存误判为失败。
- 新建模板改为：创作输入 → 正向提示词；正向、负向提示词分别连接“提示词合并”的两个端口；合并后进入模型设置 → 图片生成 → 预览 → 保存。
- “图片模型设置”负责配置，“图片生成”才调用模型；合并、预览、生图等节点不再展示没有实际作用的默认值输入框。正负端口拒绝明显接反。
- 手机端退出按钮不再覆盖保存操作；画布尺寸改变后重新适配，避免桌面切手机后节点全部落在视口外。

## 执行与异常修复

- 分支按节点来源保留正负提示词，公共祖先只计一次，负向条件不会混入正向提示词。仍兼容原有串行图。
- 合并时显式参数优先于继承默认值；独立分支提供互相冲突的模型、尺寸、参考图或图片产物时，明确报错；下游对祖先设置的覆盖保留。
- 默认模型节点真正清除先前模型覆盖。文字生成结果可传给下一步图片生成。
- 说明节点通过 progress 接口完成/跳过时也写入节点状态，不再造成下游缺少上游状态。
- 发布/试运行预检检查关键数据依赖，包括空提示词、没有上游的合并、没有图片来源的保存，允许正负提示词独立作为数据源，不强迫添加形式上的输入节点。
- 保存版本前锁定所属工作流行，避免并发取相同版本号。
- 普通运行不会因用户是教师/运营/管理员而暗中切到其他作者的草稿；明确选定草稿版本的试运行仍按权限检查。
- 前端阻止重复提交；后端执行增加唯一令牌，旧请求不能覆盖或解锁较新的执行。恢复陈旧锁后不会把旧锁重新保存到下一节点。
- 20 分钟保留策略继续生效，过期未完成任务转为结束状态，清理队列占用；运行历史明确显示已过期。
- 浏览器草稿存储包含工作流元数据，存储空间不足会提示服务器保存；保存期间防止继续改图，退出后不再启动尚未提交的试运行。
