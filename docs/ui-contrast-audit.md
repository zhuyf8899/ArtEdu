# 排版体检：文字与背景同色的排查与修复（2026-09-27）

针对"Web Coding 普遍存在的 CSS 样式显示问题（按钮文字看不见、文字被底色吞掉）"，
做了一次可复现的自动排查，而不是逐页凭肉眼找。

## 方法

用生产构建 + 桩 API 在 headless Chrome 里逐页扫描：取每个"直接含文字"的元素，
沿祖先链找到它真正压着的底色（自己画底色的元素用自身背景），按 WCAG 公式算对比度；
对比度低于 1.6 视为"几乎同色"。渐变背景读不出单一底色，自动判定会误报，单独用截图人工确认。

覆盖页面：首页、教学资源库、设计工作台、案例社区、我的学习、创作对话。

## 已修（两处真实缺陷）

1. **案例社区：没有封面图的案例卡，标题后半截"消失"**。
   兜底封面是 135° 对角渐变（深 / 浅），标题与副标题是白字（`.work-visual-fallback strong/small`），
   文字横向延伸时压到浅色半边就看不见了。浅色半边压暗为 `#3f3f3f`（白字对比度 1.17 → 10.53），
   对角构图保留。
2. **设计工作台：`// DESIGN TOOLBOX` 眉标几乎不可见**。
   眉标颜色来自与首页深色问卷卡共用的选择器（`.course-discovery p, .tool-directory p { color: #c9f44e }`），
   荧光绿压在浅底工具箱面板上对比度只有 1.18。为 `.tool-directory p` 单独指定 `#5b6b1a`（对比度 5.48）。

两处修复后重跑扫描，六个页面均为 0 处"几乎同色"。

## 边界

- 自动扫描只能发现"颜色与背景重合"，发现不了元素互相遮挡（例如绝对定位盖住文字）。
  这类需要按页面人工过一遍，建议在交付前对着桌面/窄屏两种宽度各看一遍。
- 渐变、图片、半透明蒙层上的文字不参与自动判定，靠截图确认；本次已确认的截图见验收留档。

## 复现

```powershell
cd admin-console; npm run build
# 桩 API + headless Chrome 扫描（脚本在会诊留档目录）
node ui-contrast-check.mjs
```
