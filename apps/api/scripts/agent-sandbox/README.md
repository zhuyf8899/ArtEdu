- `previews/`：脚本案例和先前真实模型生成的离线文件。

## 源码阅读顺序

1. `policy.mjs`：任务合同、只读/创建/修改区分，分支上下文、交付验收与进度视图模型。
2. `runtime.ts`：实际模型/工具循环候选。最后一轮禁用新工具；拦截截断参数；保留部分成果；区分检查失败、等待确认、暂停。
3. `tools.ts`：复用实际平台工具，只对文档继承上下文和网页静态检查增加候选行为。
4. `build-candidate.ts`：精确替换源码锚点生成 Harness 副本；锚点变化会拒绝继续，避免静默用错版本。
5. `render.mjs`：成果卡片、明确状态和阶段的实验渲染；不依赖模型是否输出 Markdown 链接。
6. `test.ts` / `preview.ts`：自动验证和离线对照页面。

## 当前候选行为

- 前端传来的自定义 systemPrompt 不能覆盖服务端基本策略；任务合同与联网偏好由候选组合器明确生成。
- 解释、否定、引用文本不会仅因 Word/PDF/“生成图片”等关键词直接进入产物通道；多产物要求保留为数组。
- 修改任务依赖明确的上一轮产物记录；找不到记录时澄清，避免编造文件名。
- 网页要求真实文件、最新一次写入之后的有效检查。检查后再次写入会清除旧验收状态。
- 没有交付物为 failed；已有文件但缺验证/缺另一产物/调用预算耗尽为 partial；等待授权为 needs_confirmation；用户暂停为 paused。
- 成果链接从工具实际返回的 openUrl 建立。未检查的网页不会显示为“已准备好”；已有通过检查的部分成果仍可打开。
- 只读合同从工具列表移除写操作，执行层也拒绝调用未获准的工具。内部 harness_probe 不进入候选工具集。
- 文档工具继承实际讨论的文本上下文；未重新实现文档生成服务。
- 进度保留模型和工具阶段、开始/结束以及运行中/已完成/检查未通过/等待确认/暂停状态；不显示推理正文和虚构百分比。

## 限制

- 任务判断器仍是保守启发式原型，不是通用语义理解器。测试通过不代表任意否定句、跨语言或多轮任务都能正确判断。
- 任务合同/任务状态在沙箱由测试夹具提供；尚未接入生产会话、数据库状态枚举、任务恢复和服务端动作授权记录。
- 完成规则不能证明任意视觉与业务要求。新增恢复模式会在Chrome执行页面，检查可识别画廊的筛选/详情、渲染错误及移动端溢出；仍不是任意交互或审美保证。
- 上下文修复演示了分支和稳定任务状态预算，没有替换生产的历史压缩与附件管理。
- 真实输出回放只能证明验收与展示如何处理既有结果，不能证明候选提示词能让真实模型生成更好的内容。后续已完成 11 项真实 API 测试，结果见 docs/agent-sandbox-eleven-live-20261018.md。
- 后续测试覆盖真实生图与 Word 导出；复杂工作流真实执行、Office 视觉质量和跨设备会话仍未验收。

## 新增修复回归

`repair-eleven.ts --diagnostic --round=N` 是真实API驱动，N仅允许1至5，防重复计费，现有轮次不可覆盖。每轮最多60次文本与1次生图，全部11项均执行。测试桥 `server-model-bridge.cjs` 须复制到测试容器，使用服务器已有适配器；不输出密钥。生图后等待同目录 `image-review.json`，须先打开实际图片复核并绑定SHA-256，不能提前填通过。

恢复行为由 `sandboxRecovery:true` 开启，`sandboxRounds` 限制单任务调用数。原有57项检查保留原模式作回归，`test-repairs.ts` 用恢复模式验证17个新增边界。新增Chrome HTTP检查需要允许本机网络；浏览器和Playwright路径在 `browser-check.cjs` 中，属于本机实验配置。

最后两项展示文案调整（任务总阶段、图片视觉复核标签）通过 `repair-report-check.cjs` 对全11例记录与实际浏览器的补充验证，没有再次调用模型。
