# 上传、运行诊断与部署可靠性（2026-09-16）

## 本轮范围

- 案例 MP4/WebM 默认 100 MiB，可用 `CASE_VIDEO_MAX_MIB` 调低至 10–100 MiB。图片、文档和其他业务上传保持 10 MiB，不支持直接上传 MOV/ZIP。
- 浏览器从已登录的 `/api/work-upload-policy` 读取限额，显示真实传输进度、服务器校验状态与取消按钮；失败后保留表单和已上传文件。取消不撤回已提交文件；重传相同字节时，服务端在作品行锁内按 SHA-256 复用素材。
- 视频流式写盘与校验，不把整个大视频读入内存。每案例仍最多 10 个素材，所有权与草稿状态校验不变。
- Nginx 仅对案例上传放宽请求体到 101 MiB，预留 multipart 开销。其他接口请求体 11 MiB，业务文件上限仍为 10 MiB。
- `/api/health` 表示进程存活；`/api/health/ready` 检查数据库、案例迁移字段和素材目录权限。它不代表模型供应商可用。
- 管理工作台显示访问地址、API 环境标签/版本、数据库、素材与模型配置状态；不发送数据库地址、文件路径或密钥。版本未配置时如实显示未标记。

## 本机使用

`npm run check:runtime` 只读检查 Docker、API 存活/就绪、前端和前端 API 代理，不初始化数据、不登录、不重启。Docker 不在 PATH 时设置 `ARTEDU_DOCKER_BIN`。非默认端口设置 `ARTEDU_CHECK_WEB_URL=http://localhost:4273` 与 `ARTEDU_CHECK_API_URL=http://localhost:4100`。

一键启动脚本默认不再重新写入演示种子，首次空环境需显式 `-SeedDemo`。已有数据环境不要使用 `-SeedDemo` 或 `-ForceAccounts`。日志写入已忽略的 `apps/api/data/`。Docker 或端口异常时先检查诊断输出，不要清空数据库或卷。

## 服务器备份与部署

Linux + Docker Compose v2，在维护窗口执行：

```bash
bash deploy/backup-staging.sh /受控目录/全新备份目录
bash deploy/verify-backup.sh /受控目录/全新备份目录
bash deploy/deploy-staging.sh
```

备份会短暂停止当前运行的 web/api/rag-worker，等待在途写入结束，再导出 PostgreSQL 自定义格式和上传卷，保存校验和、源代码版本及容器镜像 ID。完成或失败后恢复先前运行的服务。必须同时暂停其他外部写入者（如人工 SQL、独立 Bridge）；不满足此条件不能视为一致备份。备份失败不生成 COMPLETE，保留失败文件供排查，绝不覆盖已有目录。

部署在迁移前自动备份；数据库等待超时、备份或健康检查失败会非零退出，不再输出部署成功。初次空环境应先初始化上传卷目录；版本号由部署提交注入。代码合并不会自动执行这些服务器操作。

恢复验证仅新建无网络、无端口的临时数据库容器，真实执行 pg_restore；上传归档校验 SHA-256、gzip 和 tar 完整性。只清理自己创建的临时容器，不碰现有业务容器或卷。验证需要足够内存装入恢复的数据库，不宜直接在低内存生产服务器执行。它不是完整的文件权限/播放端到端恢复验收。

## 回滚边界

1. 保存当前故障环境，停止写入，记录故障提交和备份目录。
2. 若迁移兼容，优先用备份记录的上一版镜像重新部署并验证就绪；部署新版本前须给旧镜像保留标签，不执行镜像清理。
3. 若必须回退数据，先在隔离环境恢复备份的数据库与素材，核对案例/课程数量和文件下载。确认需要舍弃哪些备份后新增数据后，才允许切换生产数据库和上传卷。
4. **不提供默认覆盖生产数据库的自动恢复命令**。生产数据恢复须由负责人明确指定目标、备份及维护窗口。

备份含用户私有数据，须限制文件权限、加密保存并另存异机；不得提交 Git。本轮不接入学校 SSO、不轮换真实密钥、不修改生产账号、不自动发布案例。
