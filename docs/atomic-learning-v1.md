# 可复用学习原子与课程主线：首期交付

日期：2026-10-20。范围：桌面端、真实 API、增量数据库结构；不替换既有课程、课时、笔记、选课或学习进度。

## 入口与操作

- `/learning`：学习原子库。内容必须经过另一位审核人员发布后才进入公共目录。
- “完整课程”：教师/管理员创建课程，选择已发布原子，调整顺序、必修/选修、先修建议、引用理由与课程专属任务。引用固定版本，不复制教学内容。
- “我的原子学习”：按账号读取原子级阅读、练习、完成记录，保留历史版本；我的空间 → 我的课程也提供此入口。学生在本页及“我的贡献”均有独立的“上传心得”按钮，不需要教师权限；默认选择全部已发布原子，也可切换本人的已学原子，关联后保存文字与附件。可按标题、简介、学习目标和知识点搜索。没有已发布原子时明确提示，不能绕过审核连接教师草稿。
- “我的贡献”：教师的原子与课程草稿、学生主动分享的学习心得。创建/编辑表单内可多选或拖入附件；点击“保存草稿并上传附件”自动先保存草稿，再上传文件。草稿详情仍提供追加附件入口，提交审核后才公开。
- “内容审核”：教师可处理关联到自己所创建原子的待审心得；管理员/运营处理全平台原子、课程与心得。管理后台 → 内容审核 → “原子 / 课程 / 心得审核”复用同一队列与操作，不再遗漏学生心得；待审总数包含这部分内容。教师不因此获得其他教师原子下的私人投稿、草稿或教学课程发布权限。需要填写审核理由，不能审核自己的内容。
- “练习评价”：原子/课程作者及平台审核人员处理练习；学生心得内的练习由其关联源原子的教师或管理员/运营评价，避免学生作者没有教师权限造成评价断点。不能评价自己的提交。课程引用者不会因此自动获得原子所有学习者的练习隐私。
- “原有课程”：保留原课程目录、旧链接及真实学习记录。首页原有课程链接继续进入原详情。

## 原子、课程、心得的区别

原子至少包含名称、目标、学习内容、知识点、建议时长、完成方式。资源可以是正文、图片、PDF、DOCX、PPTX、文本或视频。表单内提供附件队列、大小与数量校验、上传进度、成功/失败状态及重试；部分失败不跳走，保留已保存草稿与成功附件，再次保存只上传未成功项目。成功附件不会因重试被重复上传。

教师教学、学习心得使用不同类型。心得必须挂到已发布原子上；关联选择器默认读取全部已发布原子，也可切换本人的已学记录（包含历史已发布版本）。个人草稿只对作者及平台审核人员可见，关联教师仅能读取待审版本及其附件，退回后没有持续读取私人草稿的权限。审核通过后才成为公共分支。发帖不会自动生成学习完成记录，也不会改动教师课程主线。分支与采用该原子的课程均按需展开，避免一屏显示所有连接。

审核通过或退回后自动返回待审队列，保留搜索与分页；当前页处理完会返回首个可用页。列表提供显式刷新，重新聚焦页面或恢复标签页可见时也会同步；正在编辑、评价或查看审核详情时不自动重载，避免丢失输入。

课程中的先修必须引用前面的原子，拒绝重复原子、自循环、反向先修、课程外先修及全部选修的无效主线。先修建议不锁定浏览。

## 学习与版本

- 同一个原子、同一个版本的完成记录跨课程共享；不从旧课程进度猜测新原子的掌握程度。
- 阅读完成需要学习者自我确认，明确不是教师评价或能力认证。练习类型必须提交文本说明并经教学人员评价通过。
- 课程专属任务单独提交、单独评价；不随原子完成记录跨课程迁移。
- 完整课程百分比按必修原子及对应专属任务通过数计算；选修不影响必修百分比。
- 编辑生成新草稿版本，审核期间不能覆盖内容；已发布版本正文与附件清单不变。发布新原子版本不会自动升级既有课程，也不会清空旧版本学习记录。
- 退回后必须“编辑为新草稿”再提交；旧退回版本不可追加附件或直接再次送审，防止旧审核页面对同一版本的后来修改作出决定。新草稿保留原关联与附件，学生可查看审核意见后修改。
- 首期课程升级可移除旧引用、重新选择当前公开版本并重新确认上下文和任务；仅影响新草稿，审核前不改变已有公开课程。后续可增加逐节点版本差异与一键升级确认。
- 评价需要精确提交版本；学生重新提交后，旧评价页面不能误将新提交通过。

## 数据与安全

迁移 `0040_atomic_learning.sql` 新增原子/课程稳定节点、版本、附件、学习记录、课程任务和审计表；`0041_atomic_submission_versions.sql` 增加练习并发版本保护。未改写原有业务表。

新接口集中于 `/api/atomic`，默认受现有认证守卫保护；写请求继续受原有 Origin/会话检查约束。学生不能创建教师教学/完整课程；教师只能编辑自己的内容，管理员有管理权限。审核、发布、附件写入和评价均记录审计，关键变更持有行锁。

附件继承平台流式上传、文件头/类型和大小验证。仅允许平台支持的文档、图片、视频和文本，不执行上传脚本；文件按原子及版本授权读取。视频使用原生播放器和真实 Range/HEAD 响应，避免将大视频完整读成 Blob。Office 复用无脚本沙箱预览，超出渲染上限或不支持的格式可下载原件。

所有 SQL 输入参数化；动态 SQL 表名只从固定的两种练习表中选择。正式内容没有自动初始化、伪造完成记录、自动发布或物理删除动作。

## 验收与部署

1. `npm run db:migrate`：应用增量迁移，然后构建并重启 API。
2. `npm run check:atomic`：输入、先修、权限、进度、课程专属任务计数及入口回归，纳入 `npm run check`。
3. `node scripts/verify-atomic-learning.mjs`：仅接受本地数据库，在整体回滚事务内建立临时测试账号、原子、两门课程、心得及练习，验证共享进度、附件权限、版本固定、审核、评价及过期提交保护；另外启动不监听网络端口的真实 Nest/Fastify 测试应用，用独立临时会话验证 HTTP 契约、学生选择源原子、multipart 附件上传、教师/管理员/运营审核队列、私密附件、HEAD、206/416 Range、退回重提与发布后的公共分支。检查旧课程/进度/笔记数量不变；退出时回滚全部临时账号、会话与内容，删除仅由该脚本创建的临时附件目录。
4. 运行前端全量回归及完整项目检查；浏览器核对真实教师与管理后台入口、创建与取消确认、原有目录；带内容的课程主线、详情、学生分支及教师审核操作使用独立内存样例核对，不能将其理解为正式教学内容已发布。

学生入口补充验证：`node scripts/verify-student-reflection-access.mjs` 在独立本机演示学生会话中检查学习目录、本人贡献、公开原子可读取，教师创建与审核接口仍拒绝访问；不创建内容，结束时仅注销脚本自己的会话，不改变浏览器登录态。纯学生 UI 样例可用 `/tests/fixtures/atomic-learning.html?role=student#/learning?library=learning` 检查列表按钮、关联原子选择与心得附件。

开发模式的无敏感内容 UI 样例：`/tests/fixtures/atomic-learning.html`。样例所有内容只在内存，不调用平台写入 API、不计入正式课程；运行截图保存在 Git 忽略的本地 QA 目录。

## 未包含的后续能力

AI 自动拆分/推荐、旧课批量迁移、成果文件作为作业提交、公共心得举报/撤回/下架、正式课程认证、专业画像指标联动、全站搜索聚合新原子和图形拖拽编排尚未实施。首期练习以文本说明提交；不要将这些扩展描述为已交付。

后续优先：教师选一门真实课程并确认原子拆分，第二门课程复用基础原子；补充可恢复的原子下架与心得举报；最后接入基于已发布版本和真实学习事实的 AI 建议。
