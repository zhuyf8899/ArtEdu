# Agent 执行通知与聊天记录（2026-10-17）

## 最新显示规则

按用户后续调整：主界面隐藏模型调用、任务生命周期和内部探针；每次工具调用在聊天中只显示一条名称与时间记录，开始与完成合并，不显示成功或暂停状态。仅失败记录标注“失败”并弹出通知；取消常规开始、完成及暂停通知。历史事件也按同一规则折叠。下文的全量事件说明保留为底层传输和审计行为，界面以本段为准。

React 首页和 /create 现支持执行事件：任务、每轮模型调用及每次工具调用的开始、完成、失败和中断。每个事件弹出站内通知，并以时间顺序保留在对应助手消息的执行记录中。图片/图案/文档直连生成任务也显示开始和完成；这些接口内部没有实时步骤流，不虚构内部子步骤。

服务端新增 SSE progress 事件，Agent runtime 对每轮模型及工具执行发送状态。工具失败后模型可以继续解释失败原因，因此允许“某个工具失败、整轮回答正常结束”。事件只传执行名称、ID、状态、轮次及时间，不传工具参数或原始输出。执行事件同时以 system 消息写入原 Agent Run 审计，不与最终助手回答混淆，无需数据库迁移。

主界面将事件写入现有按账号隔离的 IndexedDB 对话；刷新保留，不代表跨设备会话同步。保存按事件顺序排队，引用状态同步更新，避免高频进度写入恢复旧 pending。恢复时识别已消费的首页任务，不重复执行；遗留 streaming 记录转为中断。暂停保留已收到事件及正文，并追加中断记录和通知。Agent最终状态失败时不再显示“已完成”或生成建议追问。

验证：完整 npm run check 通过；新增模型/工具事件顺序、工具失败、模型失败/中断、字段过滤、重复事件及首页任务恢复回归。浏览器用真实模型验证多轮课程查询、读取课时、缺失课程工具失败、弹出通知、记录刷新后完全一致且不重跑，以及暂停通知和中断记录。截图：local-artifacts/qa-20261017/agent-execution-records.png。

本次仅本地修改与验收，未推送或部署服务器。旧独立 /morph/ 静态接入页未新增执行记录组件。补充发现：现有自然语言产物分类可能把“不要生成文件或图片”错误匹配为图片意图；此问题独立于执行记录，尚未在本次修改中处理。
