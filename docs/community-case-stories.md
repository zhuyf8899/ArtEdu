# 案例社区：结构化案例草稿

## 本轮范围

- 一项目一案例：简介、原作者、工具、创作方式、标签、成果图集、步骤、提示词、结果与反思。
- 创建/编辑草稿 → 预览 → 单独提交审核；保存不会自动提交或发布。
- 审核抽屉展示完整案例和私有授权说明。收集案例提交时必须有原作者、已确认的展示授权及授权说明。
- 提示词作为转义后的教学文本显示，不执行 HTML，也不调用模型。
- 修复上传生成的分层存储键无法下载的问题，兼容旧文件键，校验归属和真实文件路径，阻止目录穿越。

## 数据与 API

- 新迁移：`migrations/0021_community_case_stories.sql`，给 `works` 添加 `story_json`。
- 使用项目原有 `npm run db:migrate` 执行迁移；部署前先备份目标数据库。不要对已有环境重新执行演示数据初始化。
- `POST /api/works` 接受可选 `story`；旧调用者可不提供。
- `PUT /api/works/:workId` 只允许作者修改自己的草稿或驳回案例。审核中和已发布案例不能直接修改。
- `GET /api/works/:workId` 返回结构化内容和受保护的素材下载地址。
- `story.version = 1`，包含来源、原作者、工具、方法、封面素材 ID、步骤、反思、授权状态/说明和文档下载开关。
- 封面及步骤配图必须属于当前案例且类型为图片。默认禁止读者下载文档原件。
- 原有 teacher/admin/operator 审核访问权限保留；这类账号可以查看未发布内容。公开读取不会返回私有授权说明。
- 旧案例来源 `unspecified` 保持原提交行为；本轮授权检查不是著作权真实性验证，审核人员仍需核实来源与许可。

## 使用流程

1. 案例社区点击“新建案例草稿”，填写简介、原作者、工具和标签。
2. 添加图片/视频/文档并保存。单文件最多 10 MiB，总共最多 10 个文件。
3. 编辑草稿，选择封面及步骤配图，填写原始提示词和调整过程，再次保存预览。
4. 核实作者与展示授权后，单独提交管理员审核。文档原件下载需要另行确认许可。

ZIP 不直接作为案例发布；MOV 需要转换为支持的视频格式，webloc 只是链接而不是视频。未知工具版本、参数、作者反思不得补造。

### 导入工具使用

`scripts/import-community-cases.mjs` 默认仅预检。需要先构建 API，以使用同一套服务端契约校验：

```powershell
npm --prefix apps/api run build
node scripts/import-community-cases.mjs <本地清单路径>
```

从安全环境设置 `CASE_IMPORT_ORIGIN`、`CASE_IMPORT_USERNAME`、`CASE_IMPORT_PASSWORD`，不要将密码写进脚本、仓库或命令行参数。远端必须 HTTPS，本机允许 localhost HTTP。

```powershell
# 只保存草稿
node scripts/import-community-cases.mjs <本地清单路径> --apply
# 已核实全部展示授权时，保存并提交审核（不会批准发布）
node scripts/import-community-cases.mjs <本地清单路径> --apply --submit
```

清单格式：`{ "version": 1, "cases": [...] }`。每项包含唯一 `key`、服务端作品 `payload`、`assets: [{file, sha256}]` 和 `coverFile`；步骤可附 `imageFiles`，工具上传后映射为素材 ID。文件路径相对清单目录，禁止越界。最多 100 个案例、单案例 10 个文件、单文件 10 MiB。

工具先校验所有文件哈希、路径、数量、契约及图片归属，再进行写入；每项保存 `import-receipt.json` 回执，重跑时比对作品和文件哈希，已审核中的一致内容不重传、不重复提交。主动控制写请求间隔；429 按 Retry-After 等待。不确定的网络错误不盲目重试写请求，应检查回执后重新运行。

本地预览使用自定义端口时，需设置 `VITE_API_PROXY_TARGET=http://127.0.0.1:4100`，否则 Vite 默认代理到 4000。凭据、回执、备份与素材应保存在受控目录，不提交 Git。
