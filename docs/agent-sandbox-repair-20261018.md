## 修复实现

- `runtime.ts`：截断工具参数不执行，提供修正信息后重试；按实际文件与检查结果补齐缺项；完成文档/图片/工作流后阻止重复副作用；全部交付物验收完成即可收尾。普通执行最多 8 次模型调用，压力案例保持 3 次。
- `policy.mjs`：要求紧凑、分文件输出；每轮提供已有成果与缺项；CSS/JS 改动也会清除旧网页验收；修改已有 HTML 的依赖后，重新检查可登记实际页面产物；执行类任务不能只靠一句“已启动”成功。
- `tools.ts`：工作流确认绑定到当前用户消息中的具体动作与完整目标 ID，拒绝否定、引用、疑问句及 ID 前缀误匹配；继续复用原平台工具的验证与执行。网页检查增加隔离 Chrome 渲染、有效 SVG 颜色及可识别画廊交互检查，错误返回模型修复。
- 图片交付：文件存在不等于视觉验收；缺复核时为 partial，失败时保留具体问题。本次采用 Codex 实际打开图片复核的实验钩子，**不是已实现生产自动视觉验收**。产物卡显示“AI生成图片”“独立视觉复核通过”。
- 展示：保留成果入口与实际阶段、状态；任务总状态显示为“任务状态”，图片验收不会再误标成静态检查。最终展示调整对全部 11 例记录回放验证，不额外请求模型。

文档错误也有一部分来自此前测试桥自写的提示词遗漏了段落数量约束。本次桥接改用真实 `documentPrompt`，并保留真实结构校验和 Office 导出，不能把此前这部分夹具缺陷直接当作生产文档服务缺陷。

暂停测试改用统一截止时间，避免每次模型请求都重新计时。验收条件是实际中止及中止后无新动作；不再假设暂停之前必定只能出现一次快速请求。

图片为私有下游素材测试，测试桥使用供应商文档中面向后续处理的 `X-Enable-Watermark: 0` 参数，保留 AI 来源记录与展示标识。这个素材接口实验不代表生产成品发布与标识流程已接入；参数约定见 [SiliconFlow 官方接口文档](https://api-docs.siliconflow.cn/docs/api/images-generations-post)。
